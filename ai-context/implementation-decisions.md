# 初期実装の決定事項と検証待ち

更新日：2026-10-05

## 採用した方針

- 再接続後のX座標が保存時と違う場合は自動復元しない。
- 主画面からの左右隣接関係を幅優先でたどり、同順位ではX座標と識別子で順序を固定する。到達できない画面があれば手動調整を始めない。
- 構成ごとに最新の確定配置を1件保存する。既に一致している場合は再適用と確認を省略する。起動時にも一度照合する。
- ログイン時起動は初期状態で無効とし、ユーザーが有効化できる。
- 操作ウィンドウを閉じてもメニューバーに常駐する。ログインによる起動時は初期ウィンドウを表示せず、手動起動時には表示する。
- 仮適用後は実際の位置、主画面、X座標、表示設定を読み直す。予定した上端Y座標は完全一致を求め、指定点の高さ差は配置座標で1単位以内を暫定基準とする。
- 未確定の配置はmacOSの一時適用を使い、変更前の配置は操作中のメモリだけに保持する。設定ファイルには確定済み配置だけを保存する。
- 基準点と対象点の両方で、押下時に候補線を表示してドラッグで調整し、指定画面内で離した位置で確定する。画面外で離した場合は再操作する。
- 接続イベントは短時間まとめ、アプリ自身の配置変更で同じ構成への復元を繰り返さない。キャンセル後は構成が変わるまで再試行しない。

## 保留・実機検証

- 2026-10-05のIssue 17〜19を受け、仮適用の検証を0.4秒間隔・最大5回に変更した。一時的な取得失敗とY座標の反映待ちだけを再試行し、構成変更などは即時に取り消す。取消・新規仮適用後に古い検証処理を受け付けないトークンと、再試行の判定を計算検査で確認した。確認画面の10秒は検証成功後から数える。反映の遅い実機での動作は未確認。
- 保存構成が見つかったがX座標が違う場合は、自動復元を見送った理由と手動調整の案内を表示する。実際の再接続での確認は未実施。
- ログイン時起動はApplicationsフォルダにコピーしたアプリで有効にし、更新・移動時は無効化してから置き換え、有効にし直す手順をREADMEとビルド出力に記載した。配置や署名変更後の登録状態と実際のログインによる起動は未確認。

- 検証機のmacOSバージョンとCPU範囲は、追加ディスプレイがそろってから確認する。ビルド上の最低macOS 13は暫定値。
- 2026-09-21に3画面で4点指定後の一括仮適用、macOSからの実際の座標の読み直し、確認画面、取消を操作確認した。確定保存、再接続時の復元、指定位置でのカーソル移動の目視確認は続けて行う。
- Astraのレビューを受け、1枚への切断を含む再接続判定、仮適用直前の構成照合、切断時の部分復元と復元後の座標確認を実装した。これらの異常時動作は計算検証済みで、実際の抜き差しによる確認は未実施。
- 2026-09-24の安全性レビューを受け、確認タイマーを画面操作中も動くモードへ変更した。永続適用後の配置検証に失敗した場合は、構成が安全に一致する範囲で元の位置の永続復元を試みる。アプリ側の保存だけが失敗した場合は、macOSに保存した配置を維持し、復元プロファイルが更新されないことを案内する。
- 保存プロファイルの識別子重複、座標範囲、隣接関係を読み込み時に検証し、不正な項目は使用しない。対象外画面は画面名と物理サイズ・機種情報で判定し、判別できない外部画面を見送る。
- 2026-09-23に対象点の押下・ドラッグ・リリース操作へ変更した。3画面の測定で対象点のドラッグ後に次の基準点へ進むことと、Escで測定を中止できることを操作確認した。候補線のドラッグ中の追従と画面外リリースは実機で追加確認する。
- 2026-09-24に基準点も同じ操作へ変更した。押下だけでは次の点へ進まず、リリースで確定する。
- 強制終了、スリープ、切断中の復元、異なる表示倍率、同型モニターの識別、対象外の画面の判別、全画面表示中の入力、ログイン時起動は実機検証が必要。
- 画面名と物理情報による対象外画面判定は、仮想画面が物理画面を模倣できる場合まで保証しない。Sidecar・AirPlay・各種仮想画面での見送りと、正規の外部画面が誤って除外されないことを実機で確認する。
- 永続保存後にアプリ側の保存が失敗した場合、現状はエラー表示して現在の配置の確認を促す。両方の保存を常に一体として完了できるかは実機検証と設計の追加対象。
- 2026-10-01のレビュー指摘を受け、メニューバー常駐、保存ファイル破損時の退避と再作成、操作中の再接続の再照合、対象外画面の理由表示、座標検証の整合、画面上端を覆うオーバーレイを実装した。メニューバーとDockの遮蔽、ログイン時起動、抜き差し時の自動復元、強制終了後の復帰は実機確認が残る。
- 2026-10-05に、測定中の位置変更では自動復元を強制せず、画面の組み合わせが変わった場合だけ再照合するよう変更した。Issue 16を受け、ログインによる起動は`applicationDidFinishLaunching`で`currentAppleEvent`を直接読み、open-applicationイベントのログイン項目の印から判定するよう修正した。イベントや印が得られなければ、待ち時間なしでウィンドウを表示する。合成イベントによる判定検査を追加した。`SMAppService.mainApp`による実際のログイン起動で印が届くかは、ログインし直して確認する必要があり未確認。複数画面での自動復元も、現在シングルディスプレイのため実機確認が残る。
