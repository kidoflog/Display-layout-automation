# DisplayHeight

macOS向けディスプレイ高さ調整アプリの初期実装。要件は[要件定義書](ai-context/display-alignment-requirements.md)を参照。

## 現在の実装

- 主画面を基準とする左右隣接画面の測定順序と、3枚以上の連鎖計算
- 各画面の透明オーバーレイでの点指定とマーカー表示。基準画面・対象画面の両方でドラッグ中に候補線が追従
- 全組の測定後の一括仮適用、実際の配置の読み直し、10秒以内の確定／取消
- 確定した構成ごとの配置をApplication Supportに保存
- 起動時と再接続時の構成照合、自動仮適用、キャンセル後の繰り返し抑止
- 切断で1枚になった状態も再接続判定に記録し、仮適用直前に構成を再照合
- 確認中の切断では接続中の画面で復元できる位置を試み、復元後の実座標を確認
- 確認中の操作追跡による10秒タイマーの遅延を抑止し、永続保存後の配置不一致では安全な範囲で永続復元を試行
- 不正な保存プロファイルを読み飛ばし、画面名・物理情報で対象外画面や判別不能な画面を見送る
- 保存ファイル全体が壊れた場合は元ファイルを退避し、新しい保存を作成
- メニューバーから調整画面の表示と終了ができ、ウィンドウを閉じても再接続の監視を続ける
- ログイン時起動の切り替え（macOS 13以降）

## ビルドと検証

macOS 13以降とSwift 6が必要。XcodeまたはCommand Line Toolsを使用する。

```sh
bash scripts/run-checks.sh
bash scripts/build-app.sh
```

アプリは`.build/DisplayHeight.app`に作成される。SwiftPMが動かない環境では、スクリプトが`swiftc`に切り替える。3画面で4点指定後の一括仮適用、macOSからの位置の読み直し、確認画面、取消を操作確認済み。対象点のドラッグ後に次の点へ進むことも確認済み。確定保存・再接続時の復元・カーソル移動の目視確認は未実施。開発環境にはXcode本体がないため、標準の`swift test`は使わず、計算部分と保存処理の検査スクリプトを使う。

## 操作上の注意

画面が3枚の場合は2組、合計4点を指定する。各画面の黄色い枠と「1/4点目」から「4/4点目」までの案内に従う。基準画面・対象画面の両方で、押すと表示される線をドラッグして、画面内で離すと確定する。画面外で離した場合は再操作できる。全点の入力後に一括で仮適用し、主画面に表示される確認画面で10秒以内に「確定して保存」を押す。確認しなければ元の配置に戻る。指定点から計算した移動量が0の場合は配置を変更せず、その旨を表示する。

ウィンドウを閉じてもアプリはメニューバーに残る。メニューバーの「↕︎」から調整画面を開くか、アプリを終了できる。ログインによる自動起動時は操作ウィンドウを表示せず、手動起動時は表示する。自動復元の確認時には操作ウィンドウを表示する。

ログイン時起動を使う場合は、次の手順でアプリを配置する。

1. `bash scripts/build-app.sh` でビルドする。
2. `.build/DisplayHeight.app` を `/Applications` または `~/Applications` へコピーする。
3. コピーしたアプリを起動し、「ログイン時に起動」を有効にする。
4. 更新時は、古いアプリでログイン時起動を無効にして終了し、コピーし直したアプリを起動して有効にし直す。移動するときも同じ手順を使う。

`.build` はビルド用の一時的な場所であり、削除・再作成や署名の変更によってログイン時起動が働かなくなる可能性がある。実際のログイン時起動は実機確認が残っている。

## 実機検証が必要な事項

- 3枚以上での一括適用、macOSの位置補正、異なる表示倍率での点の対応
- 強制終了、スリープ、ログアウト、接続変更時の復元動作
- 切断・再接続を伴う自動復元と、切断中の部分復元の実機確認
- Sidecar、AirPlay、仮想画面の除外判定と、物理画面の誤判定（画面名・物理情報による判定は完全な識別を保証しない）
- 同型モニターやポート・ドック変更後の識別子の安定性
- 全画面表示中のオーバーレイとEsc操作
- 実機に合わせた最低対応macOSとCPU範囲

初期実装はmacOS 13以降を暫定のビルド対象とする。対応範囲と上記の動作は実機検証後に確定する。
